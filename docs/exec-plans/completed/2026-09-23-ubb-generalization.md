# UBB 通用解析与 CC98 预设重构

## 背景

当前 `createUbbRegistry()` 能定义标签和输出，但 `parseUbb()` 默认读取 CC98 标签表，标签参数的 tokenizer 也固定为旧站格式。`completed/2026-07-08-ubb-migration.md` 已评估 BBob：其参数、纯文本标签和容错语义与 CC98 差异较大，不作为本次重构的解析底座。

## 目标

- 根入口提供不依赖 CC98 的标签注册、解析、AST 和泛型渲染能力。
- 默认支持常见的 `[tag=value]`；允许在创建注册器时传入标签头解析函数，自行决定参数模型。解析失败按原文保留。
- CC98 的标签模式、动态标签族、参数 tokenizer、表情资源和字符串输出放在显式的 CC98 入口。
- 网站的 Vue 输出、现有 CC98 AST 和 HTML/Markdown 输出维持原行为。

## 方案

解析器读取由注册器提供的标签头解析函数，得到小写标签名和 `UbbAttrs`。解析模式仍由注册器按标签名决定。通用默认解析函数只处理名称与可选等号值；CC98 使用现有 tokenizer 和参数映射。结束标签、未闭合标签和未知标签继续保留现有容错机制。对外以 `createUbbRegistry()` 和 `cc98Registry` 为入口，不引入额外的方言对象；HTML/Markdown 保持独立的 CC98 预设子路径。旧的隐式 CC98 根入口直接删除。

- `@cc98/ubb/cc98` 单独提供 `cc98Registry`、标签表和表情规则；原有 HTML、Markdown 和 Vue 输出沿用 CC98 规则。
