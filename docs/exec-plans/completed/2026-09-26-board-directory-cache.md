# 全站版面目录缓存

## 背景

网站已有 `/board/all` 查询，但只有版面列表和主题管理使用。新帖、搜索、关注、用户中心等页面分别按 ID 请求 `/board/`，即使需要的版面已包含在完整目录中，也会产生批量请求。真实匿名响应包含 12 个分组、267 个版面，约 65 KB。

## 目标

- 打包一份完整的 `/board/all` 快照，全站启动时立即可用。
- 每次应用启动后台刷新目录一次；刷新失败时继续使用快照。
- 全站按 ID 查询版面时优先使用共享目录，只对目录里没有的 ID 调用 `/board/`。
- 版面列表使用同一份目录数据。版面详情、访问权限和写作能力继续读取详情接口。

## 方案

快照保留 `/board/all` 的完整分组与版面概要，作为 Vue Query 的 `boards` 初始数据。应用启动时发起一次后台刷新，成功后更新同一个查询缓存；在当前应用实例内保持该缓存，不另建 Pinia store。现有 `boardsByIdsQuery` 统一从目录选择已知版面，仅对未知 ID 走批量接口，新帖页直接从目录计算版面映射。详情接口继续按登录状态和版面 ID 查询。

快照来自公开接口，生成时写入仓库并经 schema 校验，不让生产构建依赖论坛 API。版面结构变化时更新快照；未收录的新 ID 通过实时接口兜底。

## 验证

- `vp run ready`。
- 浏览器检查版面列表、新帖、关注版面和用户中心，记录启动刷新与按 ID 补查请求。
- 用受控接口响应验证快照先显示、刷新后更新和刷新失败后保留快照。

## 结果与验证

- 打包的公开目录含 12 个分组、267 个唯一版面 ID。`boardsQuery` 在启动时刷新一次，已知版面由目录提供；关注版面页为了展示独立 `logoUri`，继续按登录用户查询详情。
- 真实浏览器登录验收：新帖、关注流和个人中心未发额外版面查询，关注版面页发一次详情批量请求。直接查询两个已知 ID 未发 HTTP 请求；目录外 ID 发起了 `/board/?id=999999`，真实服务返回 404。
- 断开 `/board/all` 后重载版面列表，页面仍显示打包快照。恢复接口后重载，似水流年的今日回复数从快照的 537 更新为实时响应的 643。正常启动只观察到一次 `/board/all` GET。
- `vp check`、`vp run ready` 均通过，网站 313 项测试通过。项目目前没有专门的目录缓存自动化测试；该查询路径由真实浏览器验收覆盖。

## 遗留项

快照随版本发布更新，部署前应按需重新获取公开 `/board/all` 数据。现有端到端开发入口仍存在 portless 路由与 Vite 实际监听端口不一致的问题，本次使用 `localhost:5173` 验收。
