# 新帖阅读流重构

## 背景

`NewTopicsView` 把经典列表、卡片列表和只看媒体放在同一个模式变量中。前两者使用 `/topic/new`，只看媒体使用 `/topic/new-media`。模式同时决定接口、布局、侧栏和服务端保存的 `topicViewMode`，导致默认偏好尚未加载时可能先请求普通新帖，再切换到媒体请求。

版面与作者资料查询以已加载的全部主题 ID 组成 query key。每次新增一页，只要 ID 集合变化，就会重新请求整批旧 ID。旧站通过内置版面字典和本地缓存减少请求；本次先保留实时接口，只补查未知 ID。

## 目标

- 普通新帖固定使用一份 `/topic/new` 无限查询，经典与卡片只改变展示样式。
- 移除“只看媒体”，新帖页不再调用 `/topic/new-media`。
- 在现有“个人中心 → 修改资料”中设置阅读样式，并与当前服务端偏好兼容。
- 版面和作者资料只批量查询尚未取得的 ID；卡片侧栏的版面需求与主题列表合并。
- 页面刷新、翻页、返回、匿名状态和失败重试的行为明确，用户文档与实际界面一致。

## 方案

新帖页只展示 `/topic/new` 的结果，经典与卡片仅改变布局。阅读样式由 `/me.topicViewMode` 决定，在现有用户设置页保存。旧的 `?view=` 链接继续打开新帖页，查询参数不再改变内容范围或阅读样式。

关联实体查询继续使用 `/board/` 和 `/user/basic` 的批量接口。从已有批量查询缓存恢复资料，以 ID 为粒度记录已取得数据，新增页面只发缺失 ID；请求失败后允许重试，匿名主题不查作者。卡片侧栏与主题列表合并版面需求。实现应避免为每个主题独立创建网络请求。

`topicViewMode=2` 是旧协议中的媒体模式，读取时回退为经典列表。用户主动保存阅读样式后，写回 0 或 1。
