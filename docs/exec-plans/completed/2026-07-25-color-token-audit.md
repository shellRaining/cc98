# 全站颜色 token 审计

> 状态：已完成。业务源码颜色字面量已清零，自动检查和亮暗模式回归均已通过。

## 背景

登录页暗色问题暴露出业务样式仍有颜色字面量。初步扫描在 `apps/website/src` 中找到 47 个文件、179 处十六进制颜色、颜色函数、颜色名或原始 UnoCSS 调色板类；其中 20 处是皮肤预览数据，其他结果需要逐项判断和迁移。

现有 `DESIGN.md` 和 `styles/global.css` 已规定业务组件只消费语义 token，但缺少自动检查，早期迁移页面仍保留了白字、状态色、阴影、遮罩和装饰渐变的固定值。部分值在浅色模式下正常，切到暗色皮肤后会出现对比度不足、表面过亮或视觉强度不一致。

## 目标

- 清理业务页面和组件中的颜色字面量，让明暗模式与皮肤切换统一经过语义 token。
- 补齐反色表面、阴影、高光和特殊状态所需的语义，避免把所有场景硬塞进 `primary`、`surface` 或 `text`。
- 让年度报告等独立视觉区域按语义角色使用主题色，不改变其信息结构和主题气质。
- 增加自动检查，阻止业务源码重新引入未经允许的颜色字面量。
- 完成全量质量门槛与浏览器亮暗模式回归。

## 审计边界

下列位置可以保留具体颜色，它们是颜色事实源或外部协议要求：

- `DESIGN.md`、`styles/global.css` 与 `styles/skins.css` 中的调色板和皮肤变量。
- `stores/skins.ts` 的皮肤预览色，数值属于皮肤注册数据。
- PWA manifest、HTML `theme-color` 等必须输出具体颜色字符串的浏览器元数据。
- 测试样本、用户提交的富内容颜色和管理操作传给服务端的颜色值。
- `mask-image` 等只读取 alpha、不会作为界面颜色显示的黑白遮罩。

`transparent`、`currentColor` 和继承值不属于颜色字面量违规。图片素材单独按视觉结果验收，不对像素颜色做源码扫描。

## 方案

颜色分为三类处理：普通界面颜色直接映射到现有语义 token；阴影、高光、媒体工具条等跨组件稳定场景增加专用语义 token；年度报告和首页论坛统计这类独立视觉模块按强调、警告、成功等语义复用主题色，并通过 `color-mix()` 派生局部高光和渐变。

自动检查扫描 `apps/website/src` 的 Vue、CSS 和 TypeScript 源码，允许事实源文件与少量经过说明的协议数据。检查接入 `website#check` 和根任务的 `vp run ready`，新增违规时直接失败并打印文件与行号。

## 验证结果

- `vp run website#check:colors` 通过。业务源码没有未声明的颜色字面量，唯一保留项是 `TopicModerationDialog.vue` 中传给服务端的默认高亮值，并带有 `color-literal-allowed` 说明。
- 仓库级兜底扫描只发现调色板事实源、皮肤预览数据、PWA 与 HTML 浏览器元数据、测试和用户富内容样本，没有遗漏其他应用或样式入口。
- `vp check --fix` 通过，格式、lint 和类型检查没有问题。
- `vp run ready` 通过。网站 31 个测试文件共 292 个测试通过，UBB 187 个测试通过，API 17 个测试通过，utils 1 个测试通过；Knip、构建和其余质量门槛均通过，仅保留已有的 chunk size 提示。
- 浏览器回归覆盖默认亮色与暗色首页、登录页、版面列表、首页论坛统计浮层，以及春季皮肤的亮暗版面列表。默认主题和春季皮肤下均未出现突兀白底、低对比文字或失去层级的状态色，运行时没有 CSS 或 Vite 错误。
- 主题阅读、签到、消息、用户中心和年度报告在匿名会话下会按现有权限返回登录要求或 401。本次没有伪造登录凭证，这些页面通过静态迁移、类型检查和现有测试覆盖。
