# 全站响应式适配

## 背景

首页已经能随视口收缩，但公共顶栏和多数内页仍按桌面宽度排版。宽度低于 1000px 后，顶栏会直接隐藏主导航与搜索；版面、主题、帖子、消息、个人中心、写作和管理页面仍保留固定列宽或桌面网格。PWA 进入独立窗口后会放大这些问题，手机用户容易遇到操作入口消失、横向滚动和正文过窄。

## 目标

- 保留现有高信息密度、直角面板、皮肤色和桌面端布局，在平板与手机端重新排列内容，不另做一套视觉风格。
- 公共导航、搜索、账号、分页和主要操作在 360px 宽度下仍可访问。
- 覆盖公开浏览、登录、写作、消息、个人中心、用户管理、全站管理和年度回顾等全部路由族。
- 正文、图片、代码、编辑器和对话框不撑破视口。只有表格、代码块等确实需要保留结构的内容允许局部横向滚动。
- 用桌面和手机视口走查主要页面，并把截图保存在任务对应的浏览器产物目录中。

## 非目标

- 不改变路由、接口、权限和业务流程。
- 不重做首页已经稳定的视觉结构，也不引入新的整体风格。
- 不为了手机端减少核心信息或移除管理能力。次要元信息可以换行、折叠到同一卡片内，操作仍需可达。

## 方案

响应式规则继续由布局、页面和业务组件各自持有。公共壳处理视口边距、顶栏和页脚；路由布局处理侧栏在窄屏下变成横向导航；列表项和帖子组件决定自己的字段如何换行。全局样式只补文档级防溢出规则，不把业务页面的媒体查询集中到 `global.css`。

使用两级收缩：1000px 以下进入单列或紧凑布局，640px 以下进入手机布局。手机端内容边距使用 12px，主要点击目标保持至少 40px 高。桌面端继续使用 1140px 版心和现有信息结构。

## 决策记录

- 沿用现有 1000px 收缩点，并补 640px 手机断点，避免同一组件出现过多相近断点。
- 手机端优先重排而非隐藏。仅装饰图片和重复标签可以缩小或省略，导航、搜索、状态和操作不因视口变窄而消失。
